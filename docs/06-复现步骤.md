# 06 · 从零复现（完整命令序列）

目标：在一台 **8 GB 显存的 Windows 笔记本**上，把 27B 三元模型跑起来。
下面按时间顺序，命令可以直接抄。

> 约定：所有产物放 `D:\ninfer\`，纯 ASCII 路径。中文路径会让部分引擎读不到模型。

---

## 第 0 步：确认环境

```powershell
powershell -ExecutionPolicy Bypass -File scripts\check-env.ps1
```

需要确认的关键项：

- GPU 是 **sm_120**（50 系）→ 用 `sm_120a` 引擎
- 显存 ≥ 8 GB
- 驱动 CUDA UMD ≥ 13.1

---

## 路线 A：NInfer（推荐，GPU 全驻留）

### A1. 拿引擎包

`infer-engine-sm120a-20261002.zip`（1.26 GB）。解压后结构：

```
infer-engine-sm120a-20261002\
├─ engine\
│  ├─ ninfer-serve-120a.exe     1.27 GB
│  ├─ cudart64_13.dll  cublas64_13.dll  cublasLt64_13.dll
│  └─ avcodec-63.dll  avformat-63.dll  avutil-61.dll  swscale-10.dll  libcurl-x64.dll
├─ models\                       ← 模型放这里
├─ start-8g.bat                  8 GB 档启动器
├─ start-8g-long.bat             长上下文档
└─ SHA256SUMS.txt
```

> 这个包**自带全部运行库**，不需要另装 CUDA Toolkit。

### A2. 拿模型（关键：选对变体）

要 **`bonsai2_27b_ternary_ptq1_native_mtp.ninfer`（5.96 GB）**。

不要用完整版（9.08 GB）或 `mtponly`（7.13 GB）——它们在这个显存上差约 196 MiB 装不下。
原因见 [02](02-NInfer部署与踩坑.md)。

### A3. 启动

```bat
cd /d D:\ninfer\infer-engine-sm120a-20261002
start-8g.bat
```

或者手动（等价，但能看清参数）：

```bat
engine\ninfer-serve-120a.exe models\bonsai2_27b_ternary_ptq1_native_mtp.ninfer ^
  --host 127.0.0.1 --port 8095 --model-id ninfer-local ^
  --kv-capacity auto --kv-headroom-mib 512 --kv-dtype rk4v4-e8 ^
  --max-context 131072 --max-concurrency 1 --prefill-chunk 256 ^
  --gdn-state-fp16 --no-cuda-graph --host-kv-mib 8192 ^
  --default-reasoning-effort none --default-max-tokens 1024
```

启动约 40 秒（含设备校准）。日志里看到 `engine ready` 和端口监听就好了。

### A4. 验证

```powershell
Invoke-RestMethod http://127.0.0.1:8095/v1/models
```

应该返回 `{"data":[{"id":"ninfer-local","context_window":131072,...}]}`。

跑一次基准：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\bench-api.ps1
```

期望输出：

```
Count from 1 to 40 ... → 150 tokens / 6.4s → 23.4 tok/s
```

引擎自己的日志会给出更准的数（`decode 24.3 tok/s`）。

## 路线 B：llama.cpp + GGUF（备选，CPU 也能跑）

### B1. 装 MSVC

```powershell
curl.exe -sSL -o vs_BuildTools.exe https://aka.ms/vs/17/release/vs_BuildTools.exe
Start-Process .\vs_BuildTools.exe -Wait -ArgumentList @(
  '--quiet','--wait','--norestart','--nocache',
  '--add','Microsoft.VisualStudio.Workload.VCTools',
  '--add','Microsoft.VisualStudio.Component.VC.CMake.Project',
  '--includeRecommended')
```

**要手动点 UAC 的「是」。**

### B2. 装便携 git

```powershell
curl.exe -sSL -o mingit.zip `
  https://registry.npmmirror.com/-/binary/git-for-windows/v2.56.0.windows.2/MinGit-2.56.0.2-64-bit.zip
Expand-Archive mingit.zip -DestinationPath D:\ninfer\tools\git -Force
```

### B3. 克隆源码

```powershell
$git = 'D:\ninfer\tools\git\cmd\git.exe'
& $git -c filter.lfs.smudge= -c filter.lfs.required=false -c filter.lfs.process= `
    -c http.postBuffer=524288000 clone --depth 1 `
    https://hf-mirror.com/OpenTransformer/llama.cpp-prismml D:\ninfer\src\llama.cpp-prismml
```

### B4. 编译

```bat
scripts\build-llama-cpp-cpu.bat
```

约 90 秒出 `build-cpu\bin\llama-cli.exe`。

### B5. 拿一个"上游能读"的模型

必须确认类型号 ≤ 41。目前 27B 没有上游可用的三元 GGUF，
**只有 8B 有**：`Minarut/Ternary-Bonsai-8B-GGUF-llamacpp-compatible` 的 `TQ2_0`（1.97 GiB）。

```powershell
curl.exe -sSL --retry 20 -C - -o D:\ninfer\models\Ternary-Bonsai-8B-TQ2_0.gguf `
  https://hf-mirror.com/Minarut/Ternary-Bonsai-8B-GGUF-llamacpp-compatible/resolve/main/Ternary-Bonsai-8B-TQ2_0.gguf
```

### B6. 跑

```bat
scripts\run-llama-cli.bat
```

期望：

```
> 17+25=?
17 + 25 = 42
[ Prompt: 8.2 t/s | Generation: 14.1 t/s ]
```

## 排错对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| `only 0 bytes are available for runtime capacity` | 权重就把显存吃满 | 换更小的模型变体 |
| `available after weights` 和需求差 <300 MiB | 变体还是太大 | 同上，不要调参 |
| `unsupported logical projection geometry` | 模型形状和引擎不匹配 | 引擎是为特定模型编译的，换模型或换引擎 |
| `invalid ggml type 143` | GGUF 是 PrismML 私有打包 | 换 `TQ2_0` 版本或换引擎 |
| `unsupported tensor ... size overflows`（Ollama） | 同上 | 同上 |
| `--lm-head-q4 requires ... Q8_G32` | 模型存储格式不满足 | 去掉该参数 |
| `--kv-headroom-mib requires --kv-capacity auto` | 参数依赖 | 两个一起给 |
| `--wddm-evictable-budget needs ... NINFER_D3D12_RESIDENCY=ON` | 构建未编入 | 去掉该参数 |
| `git-lfs filter-process: command not found` | MinGit 无 lfs | 禁 LFS filter 再 clone |
| `curl: (28) Operation timed out` 且只下到几 MB | 镜像限流 | 改单流 `-C -` |
| `http=429` | 并发太多被限流 | 降到单流，等几分钟 |

## 硬件层面的现实

8 GB 显存放 27B 三元是**刚好卡住**：

```
显存 8,151 MiB
权重 ~5,500 MiB（ptq1_native_mtp 变体）
运行时 + KV + 工作区 ~1,700 MiB
──────────────────────────
剩余 ~680 MiB 给系统
```

这意味着：

- 桌面占太多（浏览器、游戏、录屏）就会 OOM
- 上下文开到 131072 时池是按主机内存检索的，别同时开别的重活
- 想要舒服的余量，12 GB 显存是分水岭
