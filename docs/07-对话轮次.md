# 07 · 对话轮次记录：一次真实的排查过程

> 这份记录按"提问 → 动作 → 结果"还原了整个晚上。
> 写下来的原因：**结论看起来简单，过程一片狼藉**。看到别人也绕了这么多弯路，可能比只看到结论更有用。

---

## 第 1 轮 · 接手台账

**提问**：读交接说明，按里面的分工干活。

**动作**：读 `TASK-RUNBOOK.md`，盘点脚本清单；实测 Ollama、python-docx、QQ 桥接是否在线；跑了一遍维尼夏角色卡的自检脚本。

**结果**：工具链健康。发现自检脚本有盲区——它只扫段落不扫表格，导致"神智 4"误报为缺失。

---

## 第 2 轮 · 启动本地模型窗口

**提问**：把 q3 进程拉起来给我看一眼。

**动作**：三次尝试才成功：

1. `Start-Process` 起的 cmd —— 调用结束就被连带清理（子进程随任务回收）
2. 第二次同上，活不过一次工具调用
3. 改用后台任务托管 + `WaitForExit` 才活下来

**结果**：窗口起来了，但 `ollama run` 立刻报错：

```
Error: open C:\Users\<user>\.ollama\history: Access is denied.
```

原因：交互式会话要写历史文件，而沙箱只允许写工作区。
解法：把 `USERPROFILE` 指到临时目录，再用 `OLLAMA_MODELS` 把模型目录指回原处。

**教训**：沙箱环境下，进程存活和文件权限是两个独立的坑，会同时出现。

---

## 第 3 轮 · 可行性校验（本项目的起点）

**提问**：给了 GitHub / 魔搭 / 夸克三个链接，要求先不部署，判断这台电脑能不能跑。

**动作**：读 README → 确认架构要求（`sm_80/86/89/120a` 白名单）；实测显卡、驱动、CUDA、内存、磁盘。

**结果**：

| 项 | 判断 |
|---|---|
| 显卡 | RTX 5060 Laptop，compute_cap 12.0 → 需要 `sm_120a` 引擎 ✅ |
| 显存 | 8,151 MiB —— 属于"刚好卡住"的档位 ⚠️ |
| 内存 | 15.2 GB —— 官方模板要 16 GiB 主机 KV，装不下 ⚠️ |
| 驱动 | 617.14 / CUDA UMD 13.4 ✅ |
| 运行库 | CUDA/cuDNN/FFmpeg/libcurl **全都没有** ❌ |

当时给出的结论是"能跑，但属于紧档"，事后看这个结论**方向对了，细节错了**。

## 第 4 轮 · 补依赖与自我校验

**提问**：补依赖，然后下载模型做自检。

**动作与受阻**：这一轮几乎全在跟网络和网盘搏斗。

| 尝试 | 结果 |
|---|---|
| `pypi.org` 直连 | 超时，改用清华/阿里镜像 |
| 镜像上的 `nvidia-cuda-runtime-cu13` | 是空壳包（0.0.0a0，无二进制） |
| GitHub 直连 | 超时；`api.github.com` 却通 |
| 夸克分享页 | 带正常 UA 能读文件清单，下载接口 404（必须登录） |
| 夸克客户端下载 | 提示"空间不足"，配额 122.6G/10G |
| hf-mirror 大文件 | 单流 0.16~6 MB/s 波动，多路并发全部卡 0 字节 |

**结果**：模型从 HF 镜像下到了（8.87 GB），自检 **PASS**（SHA256、长度、容器 v3 全对）。
但引擎始终没拿到——夸克配额满了，GitHub 资产下载被限到 0.07 MB/s。

## 第 5 轮 · 显卡超频？

**提问**：显卡超频呢？

**动作**：解释超频只提频率不改容量。顺手查了引擎是否能把权重卸载到 CPU。

**结果**：扫完 1.27 GB 二进制，提取 43 个 `NINFER_*` 环境变量和 44 个 CLI 参数——
**没有"文本权重放主机"的开关**，只有 KV 和检查点可以。这个引擎是纯 CUDA 实现，没有 CPU 计算后端。

**教训**：容量问题不是调度问题。少 200 MB 就是少 200 MB。

---

## 第 6 轮 · 换引擎（第一次碰壁）

**提问**：换引擎。

**动作**：查 Ollama 能否加载三元 GGUF。

**结果**：

```
Error: unsupported tensor "token_embd.weight" size overflows
```

作者在 README 里早写了："These files need our llama.cpp build. Stock llama.cpp will **not** run these files."

后来还发现镜像分支和产文件的 fork 不是同一支（类型号 143 vs 上限 41）。

## 第 7 轮 · 从零编译 llama.cpp

**提问**：好，换引擎（继续）。

**动作**：装 MSVC BuildTools（要用户点一次 UAC）→ 便携 MinGit → 镜像克隆 → 编译。

**结果**：

```
326 个目标，90 秒编完，llama-cli.exe 可用
```

**踩到的坑**（详见 [03](03-llama.cpp编译.md)）：

- `--filter=blob:none` 克隆失败（镜像不支持 promisor）
- git-lfs 缺失导致 checkout 失败 → 要禁 LFS filter
- PowerShell `Start-Process` 把带空格的 prompt 拆成多个参数
- `.ps1` 存成无 BOM 的 UTF-8，PowerShell 5.1 按 ANSI 解析 → 中文注释直接把语法搞崩

## 第 8 轮 · 8B 三元跑通

**动作**：下载社区重打包的 `TQ2_0` 版本（1.97 GiB）。

**结果**：

```
> 17+25=?
17 + 25 = 42
[ Prompt: 8.2 t/s | Generation: 14.1 t/s ]
```

纯 CPU、16 线程、14.1 tok/s。**这是整晚第一个真正跑起来的模型。**

---

## 第 9 轮 · 转折：27B 其实早就在跑

**动作**：暂停流程里盘点进程时，发现机器上已经有一个引擎在 8095 端口服务。

**结果**：`D:\ninfer-120a` 里有一套跑通的部署，用的是
`bonsai2_27b_ternary_ptq1_native_mtp.ninfer`（**5.96 GB**）——比我一直在试的
完整版（9.08 GB）和 mtponly（7.13 GB）都小。

```
decode 24.3 tok/s | prefill 161.9 tok/s | TTFT 236 ms
显存 7,217 / 8,151 MiB
```

**这一轮是整个项目的转折点，也是最该写下来的一课**：
我花了几个小时得出"27B 装不下"的结论，而正确做法是**换一个更小的打包变体**，
再加上 `--kv-capacity auto`（让它自己按剩余显存定池），而不是手写一个数字。

---

## 第 10 轮 · 一次自己造成的事故

**动作**：为了测试脚本，同时跑了 `llama-cli`（2 GB 模型）。

**结果**：机器崩溃，DSH 进程被系统终止，它名下的引擎子进程一起消失。

**原因**：引擎用 `--host-kv-mib 8192` 锁了 8 GB **pinned**（不可换页）内存，
再加载一个 2 GB 模型就把 15.2 GB 的机器压垮了。

**教训**：跑一个引擎时不要并行跑第二个。这条已经写进 [README](../README.md) 第八节。

## 第 12 轮 · 给非程序员用的入口

**提问**：我怎么输入指令？

**动作**：引擎没有内置 WebUI（`GET /` 返回 404），于是写了一个交互式对话脚本 + 桌面快捷方式。

**结果**：中文乱码。定位到 PowerShell 5.1 的老问题——

```
响应头：application/json   ← 没有 charset
```

`Invoke-RestMethod` 在缺 charset 时按 ISO-8859-1 解码，中文全变小写拉丁扩展。
解法：用 `Invoke-WebRequest` 取原始字节，自己按 UTF-8 转。

## 复盘：三个真正有价值的结论

### 1. 选对文件比调参重要一个数量级

同一个 27B 三元模型有三种打包，体积差 3 GB：

| 变体 | 体积 | 8 GB 卡 |
|---|---|---|
| 完整版（含 vision + dflash2） | 9.08 GB | ❌ 差 196 MiB |
| mtponly（去 vision/dflash2） | 7.13 GB | ❌ 差 196 MiB |
| **ptq1_native_mtp** | **5.96 GB** | ✅ 能跑 |

而 `--kv-capacity auto` 和手写 `--kv-capacity 1024` 的区别，决定了引擎是"按剩余显存自己算"还是"撞固定预算"。

### 2. 报错要读懂，别急着调参

`only 0 bytes are available for runtime capacity` —— 这句说明权重阶段就吃满了，
再怎么调 KV 都没用。而 `available after weights = 152 MiB` 且**关掉所有程序也不变**，
说明预算是静态的，腾显存无效。读懂这两句，能省两小时。

### 3. 国内的网络环境是独立的一关

`github.com` 不通但 `api.github.com` 通；`hf-mirror` 单流 6 MB/s 但并发会被挂起；
CUDA 的 pip 包是空壳。这些都不是技术问题，但会占掉一半时间。
